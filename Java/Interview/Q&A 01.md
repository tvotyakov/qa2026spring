# Module: Variables and Types

### The Basics: What is the difference between primitive and wrapper classes in Java? Can you give examples for numeric types?

Primitives (like `int`, `double`) are  value  types  stored  in  the  **stack**,
making  them  memory-efficient  and  fast.  Wrapper  classes  (like   `Integer`,
`Double`) are objects stored in the **heap**. Wrappers allow `null`  values  and
are  required  when  working  with  **Generics**   or   **Collections**   (e.g.,
`ArrayList<Integer>`).

### Memory Management: What are the default values for local variables and class members (fields) in Java?

**Local  variables**  do  _not_  have  default  values;   using   them   without
initialization causes  a  compilation  error.  **Class  fields**,  however,  are
_initialized_ by default: `0` for  numeric  types,  `false`  for  booleans,  and
`null` for object references.

### Type Conversion: What is the difference between implicit (widening) and explicit (narrowing) casting? Provide a quick example.

**Widening (Implicit)** happens automatically when converting _a  smaller_  type
_to a larger_ one (e.g., `int` to `long`). **Narrowing (Explicit)** requires  an
explicit cast, like `(byte) myInt`, because  it  may  result  in  data  loss  or
overflow.

### Precision Issues: Why is it not recommended to use double or float for financial calculations (e.g., price in an e-commerce test)? What should you use instead?

Floating-point types (`float`, `double`)  use  binary  arithmetic  which  cannot
accurately represent powers of 10, leading to  rounding  errors.  For  financial
data, we should use `BigDecimal` for high precision and  control  over  rounding
modes, or store values as integers (representing  the  smallest  currency  unit,
like cents).

### The Constant Factor: How do you declare a constant variable in Java, and what is the naming convention?

Constants are declared using the `static final` keywords. The convention  is  to
use __UPPER_SNAKE_CASE__, for example: `static final int TIMEOUT_SECONDS = 30;`.

### Comparison Pitfalls: What happens when you compare two Integer objects using ==? Is there any difference if the values are 10 vs 1000? (This is a tricky one!)

The `==` operator compares object references, not values. However,  Java  caches
`Integer` objects for values between *-128* and *127*. So,  Integer  objects  in
that range will point to the same  cached  instance  (returning  `true`),  while
values outside that range will be different objects (returning `false`).  Always
use `.equals()` for value comparison.

### Var Keyword: Java introduced the var keyword in version 10. Can it be used for class fields? What are the limitations?

The `var` keyword is used for **Local Variable Type Inference**.  It  cannot  be
used for class fields, method parameters, or return types. Its  main  limitation
is that the variable _must be_ initialized at the time  of  declaration  so  the
compiler can infer the type.

### Overflow: What happens if you increment a variable that is already at its maximum value (e.g., Integer.MAX_VALUE + 1)?

Java does *not throw* an exception on integer _overflow_. Instead,  it  performs
two's complement wraparound. If you add 1 to  `Integer.MAX_VALUE`,  it  silently
becomes `Integer.MIN_VALUE`. If you need to catch this, you can use methods like
`Math.addExact()` which do throw an `ArithmeticException`.
